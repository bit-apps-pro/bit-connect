Do I still need an SEO plugin with Bit Connect?

Short answer: yes, for the rest of your site — but not for your community. Bit Connect now takes care of the community pages itself, and hands the right information to your SEO plugin so the two do not fight. Here is exactly who handles what, and what is still missing.

  • Who this is for anyone deciding what to install
  • SEO plugins checked 13
  • Grey lines technical detail, skip if not useful

The one-paragraph version

Your community lives inside a single WordPress page, and every discussion is a view inside it. WordPress — and therefore every SEO plugin — only ever sees that one page. So without help, Google is told that a thousand discussions are all the same page, and each of them gets the same title, the same description and the same link preview. Bit Connect fixes that from the inside: it gives every discussion, tag page and member page its own identity, and then passes that identity to Yoast, Rank Math, AIOSEO or SEOPress so they print it as if it were their own.

The expensive part is the one you cannot see. An SEO plugin doesn't just show the wrong title — it tells Google that every discussion "is really" the community home page. Google then drops the discussions from its index entirely. Bit Connect corrects that signal on every community URL. Technically: it emits a per-route canonical and removes WordPress's own conflicting rel_canonical tag.

2 · Your SEO plugin, whichever one it is

Four plugins are recognised automatically: Bit Connect quietly hands them the right title, description and link for each discussion, and they print it in their own format. You keep one SEO plugin in charge of your whole site. The rest need one setting changed, or simply don't overlap.

Plugin Status What you need to do Notes
Yoast SEO Just works Nothing Best supported. The community sitemap is even added to Yoast's own sitemap list.
Rank Math Just works Nothing Fully wired, including keeping duplicate addresses out of its sitemap.
SEOPress Just works Exclude the topic type from its sitemap Titles and previews are correct automatically; only the sitemap needs a tick.

3 · Every setting, and what it changes

Found under Bit Connect → SEO, split across six tabs — Overview, Crawling, Meta, Archives, Indexing and Sitemap. Overview is read-only: which SEO plugin was found and who is currently printing the tags, your community and sitemap addresses, how many discussions are published, and how many tag pages are open to search engines. It warns you outright if the community is members-only, or if content for crawlers has been switched off, because in either case nothing else on the screen has any effect.

Setting Default What it does What changes if you switch it
Crawling tab — content for crawlers
Server-rendered content On Sends a plain-HTML copy of discussions, replies and tag pages, so anything that cannot run JavaScript still sees the community. Off makes the community invisible to AI crawlers and link previews. Google can still read it, and the sitemap keeps working.
Topics per rendered page 30 How many discussions appear in that plain-HTML list. Anything from 1 to 200. Higher makes every page heavier for every visitor. Older discussions stay reachable through the sitemap and the older/newer links.
Meta tab — who writes the title, address and link preview
Automatic Default If one of the four recognised SEO plugins is active, it prints the tags using the information Bit Connect gives it. If not, Bit Connect prints them. Right for almost everyone.
Always Bit Connect — Bit Connect prints the tags even when an SEO plugin is active. Use this if your SEO plugin is not recognised, or is producing wrong titles on community pages.
Always my SEO plugin — Bit Connect prints nothing of its own. Only safe with a recognised plugin. Otherwise community pages get no title and no address at all.
Meta tab — structured data, for richer results
Discussion and collection schema On Describes each discussion as a forum thread with its author, dates and replies, and each listing as a collection. Off loses the forum-style result. Worth switching off only if another plugin already adds the same thing.
Breadcrumb schema On Shows the community as the parent of each discussion and tag page in search results. Off leaves results showing a bare web address.
Archives tab — one row per taxonomy, three switches each
Route All five on Serves the page itself — /topic/…, /department/…, /tag/…, /stage/…, /status/… — listing that term's discussions. Each row shows how many terms it currently covers. Off turns that address into a "not found" page, so existing links to it stop working.
Indexed — topic types, departments, tags On Offers the page to search engines rather than marking it "please don't index". These are the pages that can rank for a subject rather than for one question — people search product and tag names. Off keeps the page working for visitors but hides it from search.
Indexed — stages, statuses Off Marked "workflow" on the tab. Nobody searches "in progress" or "needs approval", and these listings change constantly. Rarely worth turning on. Unavailable while the route above is off.
In sitemap All five on Lists that taxonomy's pages in the sitemap. Anything not indexed is never listed regardless — a sitemap is a request to index.
Indexing tab — what search engines may index
Index member profiles Off Profiles work either way; this decides whether they can appear in search. On publishes member names and activity, and puts thin pages in competition with real discussions. Turn on if your members are the draw.
Index paginated list pages Off Pages 2, 3, … of the discussion list. They exist so crawlers can reach older discussions, not to rank themselves. On usually just crowds your own results.
Sitemap tab — how discussions get found
Portal sitemap On Publishes the community sitemap file that lists every discussion. Off removes the file and its robots.txt entry, and everything below it stops applying.
Announce in robots.txt On How search engines find the sitemap without you submitting it anywhere. Keep on — this is the one route that survives whichever SEO plugin owns your main sitemap.
Include portal home On Lists the community landing page as the entry point. Rarely worth switching off.
Include topics On Lists every published discussion. This is the main way deep discussions get found. Off usually means they are not.
URLs per sitemap page 2,000 Large communities are split across several sitemap pages. Anything from 100 to 50,000. Smaller pages are lighter for your server to generate.
Archives by taxonomy All on Set on the Archives tab instead, in its "In sitemap" column, so each taxonomy's three switches stay together. —

The three switches stack in one direction. A page has to be served before it can be indexed, and indexed before it is listed in the sitemap. Turning something off at any step turns off everything after it — on purpose: a sitemap that lists a page marked "please don't index this" asks search engines for two opposite things, and they trust the whole sitemap a little less for it.

4 · What's still missing

Some of these your SEO plugin already covers for the rest of the site. The ones that matter are the ones nothing covers, because they only exist inside the community.

Priority What's missing What that costs you What to do today
High Editing a discussion's title and description for search The description is taken from the first lines of the question. If those lines are vague, the Google result is vague, and nobody can override it. Ask authors to open with a clear sentence.
High Redirects when a discussion is renamed Renaming a discussion changes its address. Old links — from Google, from emails, from other sites — break silently, and nothing records that it happened. Install Redirection and add a rule when renaming.
High Marking the accepted answer for Google Google can show a solved question with its answer directly in the results. Solved discussions are the strongest content you have, and this is the format built for them. Nothing available yet.
Med-high Telling search engines about new discussions immediately New discussions wait to be found on the next crawl, which can take days. For a support community, being current is most of the value. Rank Math or AIOSEO can do this site-wide.
Medium A visible breadcrumb trail Google gets the trail, but visitors don't see one — only a "Back to all topics" link. It also means fewer internal links between related pages. —
Medium Business details for Google (name, logo, search box) Only matters if Bit Connect runs without any SEO plugin. With one installed, it already supplies this. Keep an SEO plugin installed.
Medium Multi-language communities Search engines aren't told which language version of a discussion to show to whom. —
Medium Member profiles as author pages Profiles are hidden from search rather than made useful. Expert contributors get no visible credit. Turn profiles on in the SEO screen if your members are the draw.
Medium Automatic sitemap cleanup for SEOPress and AIOSEO Yoast and Rank Math are handled automatically; with the other two, duplicate addresses stay in the sitemap until you exclude them by hand. One tick in that plugin's sitemap settings.
Low-med Image handling No automatic image descriptions and no image sitemap, so images in discussions don't surface in image search. Rank Math or AIOSEO can help site-wide.
Low Video and news sitemaps Specialist formats. Rarely relevant to a support community. —
Low "Last updated" dates on tag pages Discussions carry one; tag pages don't, so crawlers can't tell which have changed. —
Low Writing suggestions and keyword scores The green-light scoring an SEO plugin gives you when writing a post. Not really applicable to member-written questions. —
Low Internal link suggestions No prompts to link related discussions. Tag pages already do much of this work. —
Low Rankings and traffic reporting Bit Connect shows no search performance data of its own. Site Kit by Google, or your SEO plugin.
Low Editing crawler rules (robots.txt) Bit Connect only adds its sitemap line; there's no screen for custom rules. Any SEO plugin has an editor for this.
Low Fine control over paging tags Duplicate listings are already prevented; a few smaller signals about page order aren't sent. —

What we'd build next

In order — correctness first, then reach, then tidying up the plugins that currently double up.

  1. Let people edit how a discussion appears in search A title, description and image field on the discussion itself. The only gap authors can feel directly.
  2. Keep old links alive when a discussion is renamed Automatic redirects plus a log of broken links, so nothing is lost quietly.
  3. Mark accepted answers for Google Solved questions become answer results. The data already exists — it just isn't published.
  4. Recognise four more SEO plugins The SEO Framework, Slim SEO, Squirrly and SmartCrawl — so nobody has to change a setting.
  5. Clean up sitemaps for SEOPress and AIOSEO automatically Same treatment Yoast and Rank Math already get.
  6. Announce new discussions the moment they're posted Instead of waiting for the next crawl. Small change, real effect on a busy community.

Landed recently: the SEO control panel is now in the admin sidebar with all six tabs and a live status panel, and the community sitemap keeps working even if you switch off the plain-HTML fallback.
